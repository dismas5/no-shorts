# Настоящий Safari: Mac и iPhone

**Результаты не заполнены: Mac/Xcode/iPhone здесь недоступны.** Отмечайте факт прохождения, версию ОС/Safari, сборку Xcode, способ подписи и дату. Simulator и браузер WebKit не заменяют iPhone.

## Подготовка

- [ ] `npm ci && npm run check && npm run package` проходит на Mac.
- [ ] `npm run safari:generate` действительно создал app и extension targets; предупреждения конвертера разобраны.
- [ ] После конвертации manifest всё ещё содержит только три API permissions и optional HTTP/HTTPS диапазон, без required hosts и тестовых адресов.
- [ ] macOS target собран и запущен через containing app, extension включён в Safari 18.
- [ ] iOS target собран с deployment target 18.0, выбран реальный iPhone с iOS 18, оба targets подписаны, containing app установлен/запущен.
- [ ] Проверены ограничения development-signing и повторного запуска, а не только unsigned Simulator.
- [ ] Подготовлен fixture-сервер из `scripts/fixture-server.mjs`. Для телефона можно задать `LB_FIXTURE_HOST=0.0.0.0` и зайти по LAN-IP компьютера. Используйте доверенную локальную сеть; этот сервер предназначен только для теста и не является частью расширения. Остановите после проверки. При firewall/network ограничении отметьте сценарий как непроверенный.

## Доступ и UI (отдельно Mac / iPhone)

- [ ] Список пуст после первой установки; самовольного запроса «все сайты» нет.
- [ ] Введён новый домен вручную, нужен только доступ к нему по HTTP/HTTPS.
- [ ] Состояние Ask/Deny не выдаётся за активную защиту.
- [ ] Согласие через меню страницы/toolbar и Safari Settings отражается после перепроверки.
- [ ] Проверены постоянный и временный site access, истечение временного доступа и отзыв.
- [ ] При первом новом grant нет гонки с его очисткой до сохранения правила.
- [ ] Поддомены выключены/включены по отдельности, соседний домен и суффикс-двойник не затронуты.
- [ ] После удаления последнего правила доступ освобождён или явно показан как сохранённый перекрывающий grant.
- [ ] Формы удобны в portrait/landscape; нет горизонтального скролла на 320px; keyboard/VoiceOver объявляют подписи и результаты ошибок.
- [ ] Изменение сохраняет ID; удаление, валидированный импорт с превью, экспорт JSON и проверка URL работают. На iPhone проверить Files/share/download и доступность текстового JSON как резерва.

## Сеть, SPA, жизненный цикл

- [ ] `getDynamicRules()` соответствует конфигурации; нет правил для image/media/XHR.
- [ ] `isRegexSupported` подтвердил все выражения, в том числе percent-escape classes и optional subdomain prefix.
- [ ] Прямой адрес, внешняя ссылка, новая вкладка и обычный переход в site/section/exact заблокированы.
- [ ] Разрешённые пути и подресурсы работают; граница `/section-example` не блокируется.
- [ ] Query/fragment, регистр, Unicode, escapes, dot segments и trailing slash соответствуют README и совпадают с DNR.
- [ ] Скрипты `ISOLATED` и `MAIN` зарегистрированы на всём домене, document_start; переопределение history происходит именно в page world.
- [ ] pushState/replaceState сайта без network navigation блокируются. Данные поддельного page event не используются как URL.
- [ ] Ссылки в capture-фазе, Back/Forward и реальное `pageshow.persisted=true` проверены.
- [ ] Вкладка, восстановленная при запуске Safari, перепроверена.
- [ ] Изменение списка блокирует уже открытую страницу; разрешённые вкладки продолжают работать.
- [ ] Доступные audio/video, открытый shadow root и iframe-проигрыватели прекращают просмотр/воспроизведение после блокировки. Отдельно записать задержку/первый кадр; не считать отсутствие видимого видео доказательством остановки звука.
- [ ] Повторные смены/перезапуск фона не создают цикл redirect или несколько таймеров.
- [ ] Перезапуск Safari/containing app и выгрузка фона сохраняют политику и восстанавливают регистрацию.
- [ ] На iPhone: переключение приложения, блокировка экрана, заморозка вкладки, возврат и low-power mode не оставляют запрещённый экран доступным после возобновления проверки. Записать наблюдаемую задержку.
- [ ] Private Browsing включён отдельно; те же network/SPA сценарии проходят с site access.
- [ ] Каждый Safari profile настроен отдельно: проверить, что другая local-конфигурация не ошибочно принимается за общую.
- [ ] Для сравнения Safari 18.0 и актуальной версии не используются API, появившиеся только в 18.4/18.5.

## Приватность и распространение

- [ ] При работе расширения нет внешних запросов нашего runtime-кода. Отличены запросы сайта, Safari и средств подписи.
- [ ] Local storage содержит только policy/revision/epoch; console не пишет полные URL; blocked.html содержит только rule ID.
- [ ] Ошибка DNR/регистрации не показывает полную активность; перезагрузка/перепроверка исправляет состояние или явно оставляет ошибку.
- [ ] Постоянная установка проверена подписанным приложением, с подходящим для версии Safari каналом распространения.
- [ ] При обновлении сохранены список/ID, миграция схемы выполнена, ресурсы в проектах действительно обновились.
- [ ] При выключении/удалении extension штатным способом новые блокировки прекращаются; после перезагрузки документов нет старого guard.

Форма записи: `Mac/iPhone · ОС · Safari · Xcode · подпись · сценарий · результат · фактические ошибки/задержка`. Не отмечайте пункт по одному лишь наличию соответствующего кода.
