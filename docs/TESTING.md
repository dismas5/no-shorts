# Повторяемая проверка

## Автоматическая логика

```bash
npm ci
npm run check
npm run package
```

`tests/policy.test.ts`: пустой список, строгий формат, ограничения, IDN/IP, dot segments, percent-encoding, регистр, trailing slash, типы правил, протоколы, поддомены и домены-двойники. Более 15 тысяч сравнений сгенерированных regex и чистого matcher; это не проверка браузерного DNR.

`tests/controller.test.ts`: добавление с отказом, выдача доступа, редактирование, удаление и очистка grants, отзыв, повторная инициализация из storage, конфликты редакторов, ошибки storage/DNR/регистрации scripting, unsupported regex, stale messages, отсутствие URL в диагностике/странице блокировки. Отдельно гонка `permissions.onAdded` до сохранения правила и отзывчивость настроек при намеренно зависших `executeScript`/`tabs.query`: эти API не должны вызываться при применении правил.

`tests/background.test.ts`: настоящий background entrypoint в VM и настоящий request-клиент через модель портов: авторизация, очередь, сохранение/восстановление, диагностика, настройки со старым списком и зависшими API вкладок. Реальные guard/history запускаются в модели загрузки документа; переход в `/shorts` проверяется после загрузки страницы и после нового экземпляра фона. Это не запуск Safari, но проверка всей JavaScript-цепочки без подмены обработчика сообщений.

`tests/guard.test.ts`: скомпилированные настоящие guard/history скрипты в DOM-песочнице LinkeDOM: сохранение разрешённого содержимого, capture-ссылка, pushState/replaceState, события popstate/pageshow/focus, fallback, пауза media, повторное внедрение, отзыв доступа, поддельное событие страницы. Здесь History и воспроизведение моделируются; это **не доказательство native BFCache или Safari injection**.

`tests/options.test.ts`: скомпилированный UI, реальный controller и модель browser API: пустой список, ошибки валидации, CRUD, отказ/выдача, стабильность ID, JSON-превью, отказ ошибочного импорта, подтверждение импорта, экспорт и проверка URL. Браузерная отрисовка/VoiceOver и native permission prompts в этот тест не входят.

В `scripts/audit.mjs` проверяются обе готовые папки. Runtime-код не должен содержать тестовых адресов, сетевых API/remote resources, непредусмотренных permissions, static content scripts, WAR, sourcemaps, тестов или node_modules. Архивы с фиксированными timestamp и порядком файлов можно собрать дважды и сравнить SHA256SUMS.

## Настоящий Firefox

Нужны Firefox 140+, geckodriver в PATH (или `FIREFOX_BIN`, `GECKODRIVER_BIN`), Python 3 и разрешение запускать loopback HTTP/WebDriver серверы. В Windows можно указать `PYTHON_BIN=python`, если команда `python3` отсутствует. PowerShell использует `$env:FIREFOX_BIN=...` вместо POSIX-присваивания переменной.

```bash
npm run build
npm run test:firefox
# Либо:
FIREFOX_BIN=/путь/firefox GECKODRIVER_BIN=/путь/geckodriver npm run test:firefox
```

Скрипт создаёт временную копию расширения с обязательным доступом **только к localhost IPv4 теста**, устанавливает её как temporary addon через geckodriver, использует настоящий UI и HTTP fixture. Production manifest/артефакты не изменяются. Локальные разрешения в dist не попадают. Native выдачу/отказ разрешений нужно проверять вручную с production manifest.

Автоматизация проверяет empty state, сохранение правила, подтверждение DNR, отсутствие HTTP-запроса запрещённого документа на сервере, разрешённую границу пути, pushState/replaceState, capture-ссылку, новую вкладку и размеры 320/768/1024/1440. Screenshots только страницы настроек записываются в `.test-output/`. Фиксированный UUID задаётся лишь тестовому профилю; если Firefox изменит формат внутренней настройки `extensions.webextensions.uuids`, обновите этот элемент тестовой автоматизации. В текущей Linux-песочнице весь этот сценарий **не прошёл по ограничению окружения**, а не был объявлен успешным.

Для ручной проверки настоящего браузера:

```bash
node scripts/fixture-server.mjs
npm run dev:firefox
```

Откройте `http://127.0.0.1:8787/allowed`. В настройках вручную добавьте домен `127.0.0.1`, тип «Раздел», путь `/section`, без поддоменов. Это ваши тестовые данные в отдельном профиле, не предустановленный список.

| Действие | Ожидаемый результат |
| --- | --- |
| Ввести `/section`, `/section/`, `/section/item?x=1#f` в адресную строку | штатная DNR-ошибка, сервер не получает документ |
| Открыть запрещённую ссылку с другой страницы/в новой вкладке | документ не загружается; новая вкладка может показать штатную ошибку |
| `/section-example`, `/Section`, `/allowed?next=/section` | страница работает |
| Кнопки pushState/replaceState на `/allowed` | локальная страница блокировки; имя правила видно |
| Обычная ссылка в запрещённый путь | capture блокирует просмотр |
| Назад/вперёд, возврат к документу из BFCache | запрещённый текущий адрес снова останавливается; сверить реальный `pageshow persisted=true` |
| Восстановление вкладок после закрытия браузера | DNR сохраняется, guard регистрируется вновь; настройки показывают согласованное состояние |
| Проигрывать локальный tone.wav, перейти в раздел через SPA | доступный audio paused/muted; звук прекращается после замены документа |
| Открыть страницу нового сайта, затем впервые добавить правило для него в другой вкладке | настройки сохраняются; после перезагрузки сайта появляются guard/history, сеть блокирует совпадающие документы |
| Изменить правило на сайте, где guard уже работает | работающий guard получает сигнал обновления и применяет новую политику |
| Отказать в первом запросе | правило сохранено как «Нет доступа», не объявлено активным |
| Выдать доступ позже и отозвать через browser settings | состояние меняется, регистрации/правила удаляются при отзыве, список сохраняется |
| Удалить последнее правило | соответствующий grant освобождается, остальные правила не ломаются |
| Импорт сначала ошибочного, затем корректного JSON | ошибочный ничего не меняет; корректный только после превью/подтверждения |
| Приватное окно без/с разрешением | без доступа защита не обещается; с доступом повторить сеть и SPA |
| Перезагрузить/обновить extension и перезапустить browser | политика восстановлена; старые вкладки при необходимости перезагрузить |

Для проверки настоящего BFCache сначала навигируйте между разрешёнными fixture-страницами, вернитесь и убедитесь, что `pageshow persisted=true`. Затем измените правило в другой вкладке и повторите восстановление/историю. Если браузер не использовал BFCache, записывайте это как «не проверено», а не успешную проверку BFCache. Смена адреса в SPA после восстановления тоже должна срабатывать.

Проверьте целую-site и exact-правила отдельно: смените тип в UI; `/page` и `/page/` различны для exact. Для HTTPS и IDN/поддоменов используйте собственный контролируемый стенд с действительным сертификатом или стандартную разрешённую localhost-настройку браузера. Не включайте тестовые исключения/сертификаты в production. Внешние сайты не нужны для базового fixture-теста.

## Веб-логика и установленное расширение

LinkeDOM/синтетические history-события проверяют логику. Screenshot обычной HTML-страницы проверяет только layout. Playwright WebKit, если его добавить для веб-логики, не является Safari Web Extension, не проверяет Apple permissions/DNR/жизненный цикл и не считается прохождением целевой платформы.

Нативный Firefox harness тоже не покрывает всё: required test hosts обходят native optional prompts; headless не доказывает audible playback; приватный режим, реальный BFCache, session restore, подписанная установка и ОС-специфика остаются ручными сценариями. Safari — отдельный [чек-лист](SAFARI-CHECKLIST.md).
