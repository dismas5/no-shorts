# Фактический отчёт проверки

## Дополнение 2026-10-30: зависание настроек Safari

Версия 1.0.6: диагностика пользователя локализовала зависание 1.0.5 на `scripts:refresh`. До исправления добавлен регрессионный тест с никогда не завершающимся executeScript; он воспроизвёл ошибку `Settings blocked at scripts:refresh`. Удалены ручное внедрение и перечисление открытых вкладок из применения правил, вместе с обработкой ошибок удалённой функции. Сохранение, сетевые правила и регистрация document_start больше не ждут API вкладок. Существующие guards обновляются через protectionEpoch; для нового сайта/после установки нужна перезагрузка его вкладок. UI различает регистрацию и работу в уже открытой странице.

После установки 1.0.6 пользователь подтвердил устранение проблемы в Safari 17.6 на своём Mac. Это подтверждение пользовательского сценария, а не прохождение всей матрицы Safari/iOS ниже.

Прошли 66 тестов, TypeScript, обе сборки, аудит и Mozilla lint. Тест зависшего executeScript теперь проверяет сохранение, перечитывание и удаление правила без обращения к API вкладок. Дополнительно настоящий background с восстановленным списком и порт-клиентом сохраняет отзывчивость при зависших API вкладок; реальные guard/history и обработчик background проверены вместе на SPA-переходе `/watch` → `/shorts/example` и повторно с новым экземпляром фона. Пять тестов удалённой функции live injection заменены проверкой отсутствия этой зависимости; аудит не допускает executeScript в готовые пакеты. Реальная загрузка 1.0.6 в Safari требует проверки на Mac; автоматические результаты не объявляются проверкой браузера.

Версия 1.0.5: пользователь подтвердил, что пустой ответ асинхронного reconcile сохраняется и на 1.0.4, при успешном коротком handshake. Причина в настоящем Safari всё ещё не подтверждена. Весь актуальный обмен настроек/guard с фоном переведён на runtime.Port вместо одноразового sendMessage. Одна операция на соединение, без автоматического повторения записи; разрыв, некорректный ответ и таймаут явно различаются, обработчики/таймеры очищаются. Общая проверка отправителя сохраняется для обоих транспортов. Добавлен текущий этап Controller; после ошибки UI перечитывает его отдельным диагностическим соединением вне очереди.

Прошли 68 тестов, TypeScript, сборка, аудит и Mozilla lint. Новые проверки используют настоящий request-клиент и background entrypoint в VM через пару портов: сохранение/чтение/восстановление новым экземпляром фона без sendMessage, отказ авторизации, один запрос на порт, диагностика зависшего хранилища, таймаут без повтора записи, очистка и новое соединение после разрыва, некорректный ответ и ошибка отправки. Это проверка протокола и логики, а не реальный перезапуск Safari. Нужна проверка 1.0.5 на Mac.

Версия 1.0.4: в пользовательском отчёте 1.0.3 сетевые ошибки исчезли, но сохранились `MAIN:access-denied` и `ISOLATED:access-denied`. После перезапуска короткий handshake ответил, а асинхронный reconcile вернул пустой ответ. Точная причина в реальном Safari пока не установлена. Одноразовое внедрение ограничено основной страницей, чтобы не затрагивать чужие фреймы, а отказы привязаны к домену соответствующей вкладки. Асинхронный onMessage возвращает Promise вместо callback с return true; проверка адреса отправителя через tab.url сохранена. Добавлены тесты посторонних iframe, области действия отказа, консервативного статуса при неизвестном URL, задержанного хранилища и нового экземпляра background с сохранённым состоянием. Прошли 62 теста, TypeScript, сборка, аудит и Mozilla lint. Настоящий перезапуск Safari и эффективность исправления доступа требуют проверки на Mac.

Версия 1.0.3: после восстановления обмена с фоном пользователь сообщил об отказе сетевых правил, ошибке внедрения в открытые вкладки и искажении русского текста из background.js. Устранена альтернация в генерируемых DNR regex: парсер URL-фильтров WebKit её не поддерживает. Новые выражения сохраняют прежние границы путей; эквивалентность проверяется существующим перебором URL и тестом движка, отклоняющего альтернацию. JavaScript собирается в ASCII с Unicode-экранированием, проверяемым аудитом пакетов. Необязательный injectImmediately не передаётся. Ошибки сети теперь содержат этап отказа; ошибки внедрения — только фиксированные категории по world, без адресов и исходных сообщений браузера. Прошли 57 тестов, TypeScript, сборка, аудит пакетов и Mozilla lint. Реальная работа 1.0.3 в Safari 17.6 пока не подтверждена; отказ доступа к сайтам/фреймам остаётся возможной причиной ошибок внедрения.

Версия 1.0.2: пользователь подтвердил тот же пустой ответ фона на 1.0.1 в Safari 17.6. Ответы фонового обработчика переведены на `sendResponse` с `return true` для асинхронных операций. Страница настроек проверяется по точному browser-supplied URL (`sender.url`, либо `sender.tab.url` при отсутствии первого); отсутствующий `sender.id` допускается только при совпадении этого URL. Явно другой ID по-прежнему отклоняется. Для отказа отправляется структурированная ошибка. Read-only handshake проверяет доступность обработчика независимо от очереди хранилища и сообщает только версию и результаты проверок отправителя, без URL, ID, правил и истории.

После установки 1.0.2 пользователь подтвердил успешную загрузку начального состояния в Safari 17.6: версии UI/фона 1.0.2, ID отправителя совпадает, адрес настроек совпадает, источник адреса — `tab`. Это подтверждает восстановление обмена настройками с фоном на его Mac; работа блокировки и остальная матрица Safari этим сообщением не подтверждены.

Прошли 54 теста, включая выполнение реального background entrypoint в VM: callback-ответы, отсутствующий ID, tab-only URL, отклонение чужого ID/сайта/похожего пути, конфликт сохранения, handshake при зависшем хранилище и восстановление UI. Тесты обнаружили отдельные мутации закрытия асинхронного канала и снятия проверки чужого ID; исходник восстановлен. TypeScript, сборка, аудит пакетов и Mozilla lint прошли. Эти проверки подтверждают поведение обработчика в моделируемых условиях; причина на Safari и успешность исправления требуют повторной проверки на Mac. Заявленный минимум Safari 18 не изменён.

На Mac пользователя расширение установилось, но настройки остаются на «Проверка…», а сохранение недоступно. Причина сбоя в Safari пока не установлена: ожидаются версия браузера и ошибки Web Inspector.

Исправлена обработка отказа и зависания начального запроса: запросы к фону ограничены 10 секундами, статус показывает ошибку загрузки, сохранение без загруженного списка объясняет причину, доступна повторная проверка. Таймаут не отменяет уже отправленную операцию; сообщение предлагает перечитать список перед повторным сохранением.

На Ubuntu прошли TypeScript, 48 тестов, обе сборки, аудит пакетов и Mozilla lint без замечаний. Два новых DOM-теста проверяют отказ/зависание и восстановление формы. Mutation experiment с инверсией проверки загруженного состояния обнаружен тестами; исходник восстановлен. ZIP/XPI пересобраны. Исправление устраняет молчаливый отказ интерфейса, но не подтверждает устранение первопричины на Safari.

## Среда

- Ubuntu 22.04.5 LTS, x86_64 Linux 6.8, Node 22.16.0, npm 11.7.0, Python 3, zip.
- `/usr/bin/firefox` — Snap launcher, завершился из-за недоступной capability `cap_dac_override`.
- Отдельно загружен официальный Mozilla Firefox 158.0.1. `--version` работает; headless запуск в песочнице завершился кодом 139. geckodriver 0.36.0 загружен из официального репозитория Mozilla для повторяемой проверки.
- Создание loopback HTTP-сервера запрещено: `listen EPERM 127.0.0.1`. Поэтому `test:firefox` завершился **неуспехом окружения**, до установки расширения/браузерных assertions.
- Подключённых browser UI providers нет; реальный layout screenshot, keyboard и screen reader review недоступны.
- Safari, macOS, iPhone, Xcode/xcrun отсутствуют.
- Прямой npm network недоступен в песочнице. Registry-метаданные/архивы загружены разрешённым curl в временный npm-кэш; затем выполнен `npm ci --offline` с lockfile. `.npmrc` отключает lifecycle scripts; отдельная попытка разрешить install.js esbuild была отклонена sandbox (`spawnSync EPERM`), поэтому установка проверена без lifecycle scripts, с native optional package из lockfile. Кэш и бинарники не включены в проект/пакеты. Это обход ограничения доставки зависимостей, не отключение защиты браузера/ОС.

## Пройдено

- Строгая TypeScript-проверка.
- **46 отдельных автоматических тестов**. Включены UI/DOM-сценарии и ошибки API, а не только snapshots внутренней реализации. Условные домены встречаются лишь в тестах и документации.
- В одном тесте более 15 тысяч сопоставлений генератора DNR regex с программным matcher. URL сериализуются WHATWG URL; это не native DNR.
- Mutation experiment: намеренно убрана граница `/` у section-prefix matcher. Suite стала красной на граничном URL и проверке согласованности. Исходник восстановлен, тесты повторены.
- Обе WebExtension-сборки и проверка разрешений/содержимого/CSP/отсутствия runtime network APIs и внешних ресурсов.
- Mozilla `web-ext lint`: **0 errors, 0 notices, 0 warnings**.
- Синтаксическая проверка всех Node scripts и `bash -n` Apple-скриптов. На Linux Apple-скрипты явно требуют macOS, не выдают фиктивный результат.
- Проверка детерминизма Firefox/Safari пакетов, валидности ZIP/XPI, SHA256 и отсутствия тестов/локальных grants в production.
- Независимое code review: найдены и исправлены гонка выдачи permission до save, несогласованность необычных поддоменов, игнорирование per-frame injection errors. Для каждого исправления добавлены тесты. Дополнительно исправлено отображение состояния при неожиданном отказе browser API после сохранения.

## Аудит npm-зависимостей

Production dependencies отсутствуют; в расширение включается только собственный скомпилированный код. Прямые dev dependencies: TypeScript 5.9.3, esbuild 0.25.12, web-ext 10.8.0, LinkeDOM 0.18.12, типы Node/Firefox.

Официальный npm bulk advisory API для точных версий lockfile вернул **одну high severity dev-only advisory**: `web-ext → @devicefarmer/adbkit → node-forge 1.4.0`, [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv), RSA PKCS#1 v1.5 signature verification. На дату проверки npm latest node-forge — 1.4.0, то есть исправленная версия в доступном registry отсутствует. Не установлен вымышленный override и не менялся вручную криптографический код зависимости. Android ADB-путь web-ext в этом проекте не вызывается; node-forge/adbkit отсутствуют в dist и артефактах расширения. При обновлении web-ext/forge повторите аудит. Это известная граница инструментов разработки, не утверждение о чистом полном npm audit.

web-ext может обращаться к сервисам обновления/подписи как инструмент. npm-скрипты проекта отключают его фоновый update notifier через `NO_UPDATE_NOTIFIER`; команды подписи обращаются к Mozilla по назначению. Поведение runtime-пакетов проверяется отдельно.

## Не выполнено, требует другого окружения

- Установленное расширение в настоящем Firefox, включая его DNR engine, native optional permissions, restart/private/BFCache и layout. Автоматизация подготовлена в `scripts/firefox-test.mjs`, но native сценарий **не прошёл** в текущей песочнице и не объявлен готовым результатом тестирования.
- Firefox на Windows 10, Ubuntu 24.04 и macOS.
- Генерация Xcode-проектов, компиляция и подпись Apple-приложений.
- Safari 18 на Mac и iPhone iOS 18: site-access UI, регистрация MAIN world в реальном WebKit, динамические regex rules, реальный bfcache/lifecycle/freeze, audible playback, private mode, установка/обновление/удаление.
- Действительная unlisted-подпись Mozilla и Apple signing/distribution: нужны личные аккаунты/credentials пользователя; они не запрашивались и не включены в исходники.

Подготовленные сценарии: [TESTING](TESTING.md), [Mac/iPhone checklist](SAFARI-CHECKLIST.md). Список известных функциональных ограничений — в [README](../README.md#известные-границы). Наличие автоматизации, успешный компилятор и проверка документации не заменяют отметки этих сценариев на устройствах.
